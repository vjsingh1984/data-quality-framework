== Executive Summary

The Data Quality Framework is a comprehensive, extensible Python library designed for enterprise-scale data quality validation in Apache Spark environments. Built with a plugin-based architecture, it supports multiple validation engines including Amazon Deequ, Great Expectations, schema validation, and custom business logic constraints.

=== Key Features

* **Multi-Engine Support**: Seamlessly integrate Deequ, Great Expectations, schema validation, and custom engines
* **Configuration-Driven**: HOCON-based configuration with support for file, S3, ADLS, and HTTP sources
* **Spark Native**: Built for Apache Spark with distributed processing capabilities
* **Extensible Architecture**: Plugin-based design for easy addition of new validation engines
* **Enterprise Ready**: Comprehensive error handling, monitoring, and repository management

=== Business Value

* **Improved Data Quality**: Automated detection and prevention of data quality issues
* **Reduced Risk**: Early identification of data anomalies before they impact downstream systems
* **Operational Efficiency**: Automated validation pipelines reduce manual quality checks
* **Compliance**: Structured validation framework supports regulatory requirements
* **Scalability**: Distributed processing handles enterprise-scale datasets

== Architecture Overview

image::framework-overview.png[Framework Architecture, align="center"]

The Data Quality Framework follows a layered architecture pattern:

=== Configuration Layer
The framework supports multiple configuration sources through a unified interface:

* **File System**: Local and network file system configurations
* **Cloud Storage**: S3, ADLS Gen2, and other distributed storage systems
* **HTTP Sources**: REST API endpoints for dynamic configuration
* **Inline Configuration**: Programmatic configuration using HOCON format

=== Core Framework Layer
The core orchestration layer manages the entire data quality workflow:

* **DQFramework**: Main orchestrator that coordinates all components
* **Engine Loader**: Dynamic loading system using Python reflection
* **DataFrame Manager**: Spark catalog integration and data source management

=== Engine Ecosystem
Multiple validation engines provide specialized capabilities:

* **Deequ Engine**: Amazon's Deequ library for statistical data profiling
* **Great Expectations Engine**: Statistical validation and expectation management
* **Schema Validation Engine**: Data type and structural validation
* **Custom Engine**: Business-specific validation logic and constraints

== Data Flow and Processing

image::data-flow.png[Data Flow Diagram, align="center"]

The framework processes data quality rules through a well-defined sequence:

. **Configuration Loading**: Parse and validate configuration from various sources
. **DataFrame Registration**: Load and register target DataFrames from Spark catalog
. **Engine Instantiation**: Dynamically load and configure validation engines
. **Rule Execution**: Execute validation rules against target data
. **Result Aggregation**: Collect and standardize validation results
. **Repository Storage**: Persist metrics and verification results for historical tracking

== Engine Architecture

image::engine-architecture.png[Engine Architecture, align="center"]

=== Base Engine Interface

All validation engines implement the `DQEngine` abstract base class:

[source,python]
----
class DQEngine:
    def __init__(self, config: ConfigTree, dqts: int = None):
        self._config = config
        self._dqts = dqts
    
    def apply(self, dataframe: DataFrame, repository=None) -> List[Dict]:
        """Abstract method for executing validation logic"""
        pass
----

=== Engine-Specific Implementations

==== Deequ Engine
Integrates with Amazon's Deequ library for statistical data quality checks:

* **Completeness Checks**: Detect null values and missing data
* **Uniqueness Validation**: Identify duplicate records and constraint violations
* **Compliance Rules**: Custom SQL-based validation logic
* **Statistical Profiling**: Distribution analysis and outlier detection

==== Custom Engine  
Implements business-specific validation logic:

* **Rate of Change Analysis**: Time series anomaly detection
* **Distinctness by Group**: Cardinality validation within data segments
* **Lookup Validation**: Reference data integrity checks
* **Negative Value Detection**: Financial and logical consistency validation

==== Schema Validation Engine
Provides structural and type validation:

* **Data Type Validation**: Enforce column type constraints
* **Foreign Key Constraints**: Referential integrity validation
* **Not Null Constraints**: Mandatory field validation
* **Unique Constraints**: Primary and composite key validation

== Configuration Management

image::configuration-structure.png[Configuration Structure, align="center"]

=== Configuration Format

The framework uses HOCON (Human-Optimized Config Object Notation) for configuration:

[source,hocon]
----
dqframework {
  dataframes {
    customer_data = "bronze.customer_table"
    transaction_data = "bronze.transaction_table"
  }
  
  dqrules = [
    {
      name = "customer_data_quality"
      engine = "deequ"
      dataframes = ["customer_data"]
      checks = [
        {
          constraint_name = "customer_id_completeness"
          constraint = "hasCompleteness"
          columns = ["customer_id"]
          min = 0.95
          level = "Error"
        }
      ]
    }
  ]
  
  repository {
    type = "spark_catalog"
    database = "data_quality"
    metrics_table = "dq_metrics"
    verifications_table = "dq_verifications"
  }
}
----

== Constraint Types and Capabilities

image::constraint-types.png[Constraint Types, align="center"]

=== Deequ Constraints

==== Completeness Validation
Detects missing or null values in critical columns:

[source,hocon]
----
{
  constraint_name = "email_completeness"
  constraint = "hasCompleteness"
  columns = ["email"]
  min = 0.98
  level = "Error"
}
----

==== Uniqueness Validation
Ensures unique values in key columns:

[source,hocon]
----
{
  constraint_name = "customer_id_uniqueness"
  constraint = "hasUniqueness"
  columns = ["customer_id"]
  min = 1.0
  level = "Error"
}
----

==== Compliance Rules
Custom SQL-based validation logic:

[source,hocon]
----
{
  constraint_name = "email_format_compliance"
  constraint = "satisfies"
  expression = "email RLIKE '^[A-Za-z0-9+_.-]+@(.+)$'"
  min = 0.95
  level = "Warning"
}
----

=== Custom Constraints

image::custom-constraints.png[Custom Constraints, align="center"]

==== Rate of Change Analysis
Monitors time series data for anomalous changes:

[source,hocon]
----
{
  constraint_name = "price_rate_of_change"
  constraint = "RateOfChange"
  columns = ["price", "volume"]
  group_by = ["symbol", "exchange"]
  sort_by = "trade_date"
  max = 20.0
  level = "Warning"
}
----

==== Distinctness by Group
Validates cardinality within data segments:

[source,hocon]
----
{
  constraint_name = "product_distinctness"
  constraint = "DistinctnessByGroup"
  columns = ["product_id"]
  group_by = ["category", "brand"]
  min = 5
  level = "Error"
}
----

==== Lookup Validation
Ensures column names exist in reference tables:

[source,hocon]
----
{
  constraint_name = "factor_lookup_validation"
  constraint = "LookupBasedOnColumnNameList"
  ignore_columns = ["date", "source"]
  ref_table = "master.factor_list"
  ref_columns = "factor_id"
  level = "Warning"
}
----

== API Reference

=== DQFramework Class

==== Constructor
[source,python]
----
DQFramework(spark: SparkSession, config: str, default_dataframe: DataFrame = None)
----

**Parameters:**
* `spark`: Active Spark session
* `config`: Configuration string or path (file://, s3://, abfss://, http://, https://)
* `default_dataframe`: Optional default DataFrame for rules

==== Methods

===== run()
Executes all configured data quality rules.

**Returns:** `List[Dict]` - Cumulative metrics from all executed rules

[source,python]
----
results = dq_framework.run()
for result in results:
    print(f"Check: {result['check']}, Success: {result['success']}")
----

===== get_dataframe(df_name: str)
Retrieves a DataFrame by name from the configured sources.

**Parameters:**
* `df_name`: Name of the DataFrame to retrieve

**Returns:** `DataFrame` - Spark DataFrame

==== load_engine()

engine = EngineLoader().load_engine("deequ", config, timestamp)

== Troubleshooting Guide

=== Common Issues

==== Configuration Loading Errors
**Symptom:** `ConfigurationException` during framework initialization

**Solutions:**
* Verify HOCON syntax using online validators
* Check file permissions and network accessibility
* Validate configuration schema against expected structure

==== Engine Loading Failures  
**Symptom:** `ImportError` or `AttributeError` during engine instantiation

**Solutions:**
* Verify engine dependencies are installed (pydeequ, great-expectations)
* Check engine class naming conventions
* Validate engine configuration parameters

==== Spark Integration Issues
**Symptom:** JAR dependency errors or Spark context failures

**Solutions:**
* Ensure Deequ JAR is available in Spark classpath
* Verify Spark session configuration
* Check cluster connectivity and resource allocation

==== Performance Problems
**Symptom:** Slow execution or out-of-memory errors

**Solutions:**
* Increase Spark driver and executor memory
* Optimize DataFrame partitioning
* Implement incremental validation strategies
